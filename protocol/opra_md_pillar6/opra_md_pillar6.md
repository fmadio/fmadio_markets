# OPRA Pillar Binary v6 - Decoder Reference

Summary of `opra_md_pillar6/OPRA_Pillar_Output_Specification.pdf` (OPRA Binary Data
Recipient Interface Specification, Version 6.4a, July 1 2026) and
`opra_md_pillar6/OPRA_Common_IP_Multicast_Distribution_Network.pdf` (NMS Common IP
Multicast Distribution Network Recipient Interface Specification, Version 1.59,
February 9 2026), containing everything required to decode the feed from raw UDP
packets.

OPRA is the consolidated options tape: SIAC (the Processor) merges trade/quote input
from all US options exchanges (Participants) and disseminates the consolidated
stream, including the OPRA-calculated NBBO (Best Bid and Best Offer), over IP
multicast "lines".

## Protocol Stack

```
Ethernet / (VLAN) / IPv4 / UDP
  +-- OPRA Transmission Block            (21 byte header + block data + optional pad byte)
        +-- Message 1                     (12 byte message header + fixed format body)
        +-- Message 2
        +-- ...
        +-- Message N                     (N = Messages In Block field)
```

- One UDP datagram = one transmission block. Max block size 1000 bytes including
  header, data and pad byte.
- **All integer fields (block header and messages) are big endian (network byte
  order)**, unsigned unless noted; negative values are 2's complement.
- **Unlike MoldUDP64 there is no per-message length field** (except Category C which
  carries its own). Message length is derived from Message Category + Message
  Indicator; an unknown category makes the rest of the block undecodable.

## 1. Transmission Block (transport layer)

### 1.1 Block Header (21 bytes)

| Field                    | Offset | Length | Type  | Notes                                     |
|--------------------------|--------|--------|-------|-------------------------------------------|
| Version                  | 0      | 1      | NUM   | 6 (0x06) for current version              |
| Block Size               | 1      | 2      | NUM   | Size in bytes of entire block (header + data + pad) |
| Data Feed Indicator      | 3      | 1      | ASCII | 'O' for OPRA                              |
| Retransmission Indicator | 4      | 1      | ASCII | space = original, 'V' = retransmitted block |
| Session Indicator        | 5      | 1      | NUM   | See 1.2                                   |
| Block Sequence Number    | 6      | 4      | NUM   | Sequence number of FIRST message in block (see 1.3) |
| Messages In Block        | 10     | 1      | NUM   | Number of messages in the block data      |
| Block Timestamp          | 11     | 8      | NUM   | Seconds since epoch 1/1/1970 UTC (4 bytes) + nanoseconds (4 bytes) |
| Block Checksum           | 19     | 2      | NUM   | Lower 16 bits of the 32-bit sum of all bytes in the block, excluding the checksum field itself |

- Block Timestamp is the time OPRA completed processing the block. Convert to ns
  since epoch: `seconds * 1e9 + nanoseconds`. For retransmitted blocks it is the
  original processing time of the first message.
- Block Pad Byte: 1 byte 0x00 appended after the last message ONLY when the block
  would otherwise have an odd number of bytes (so Block Size is always even).
- Message categories C (Administrative) and H (Control) are always sent alone, one
  message per block. All other categories may be packed multiple per block.

### 1.2 Session Indicator

| Value       | Meaning                                                          |
|-------------|------------------------------------------------------------------|
| 0x00        | Regular Trading Hours session                                    |
| 0x01 - 0x05 | Global Trading Hours (GTH) session; value = trade day Mon(1)..Fri(5). GTH spans two calendar days (starts 8:15 pm ET previous day) |
| 'X' (0x58)  | GTH messages generated by OPRA itself (Control messages, OPRA-generated Zero Quotes) |

### 1.3 Block Sequence Number rules

The Block Sequence Number is really a per-line MESSAGE sequence number: it is the
sequence number of the first message in the block, messages after the first are
implicitly numbered sequentially (seq, seq+1, ...), and the next block's number is
incremented by the number of messages in this block. Per line, reset to zero at
start of day; rolls over after 4,294,967,295 to 1. Exceptions:

1. Retransmitted blocks ('V'): field contains the message sequence number of the
   first message in the retransmitted block.
2. Category H Type K (Reset Block Sequence Number): field contains the number the
   counter is reset to (greater than the highest previously transmitted, or 1 on
   rollover / site failure recovery / DR activation). The next block is that
   number + 1.
3. Category H Type C (Start of Day): field is zero.
4. Category H Type N (Line Integrity): field contains the sequence number of the
   LAST transmitted message; Line Integrity does not consume/increment the message
   sequence number. Sent at least every 10 seconds (can be more frequent).

Gap detection per line: `nextExpected = blockSeqNo + messagesInBlock`, skipping the
exceptions above. The A and B streams of a line carry identical payloads and
sequence ranges (arbitrate by sequence number).

### 1.4 Retransmission

Missed blocks can be re-requested via the Automated Retransmission Facility (unicast
TCP through IGN, separate Retransmission Users Guide). Retransmitted messages are
re-published on the dedicated retransmission multicast groups (section 8) with 'V'
in the Retransmission Indicator, at a lower rate. Category H Type C (Start of Day)
and Type N (Line Integrity) are never retransmitted. Not needed for PCAP decode.

### 2.1 Message Header (every message, first 12 bytes)

| Field                        | Offset | Length | Type  | Notes                           |
|------------------------------|--------|--------|-------|---------------------------------|
| Participant ID               | 0      | 1      | ASCII | Exchange that originated the message (2.2) |
| Message Category             | 1      | 1      | ASCII | See 2.3                         |

### 2.3 Message Category -> total message length (bytes, including 12 byte header)

| Category | Meaning                            | Types                     | Length |
|----------|------------------------------------|---------------------------|--------|
| a        | Equity and Index Last Sale         | A-J, S, a-v               | 43 |
| d        | Open Interest                      | space                     | 30 |
| f        | Equity and Index End of Day Summary| space                     | 72 |
| k        | Long Equity and Index Quote        | space, A B C F I O R T X Y| 43 + BBO appendage (0/10/20) |
| q        | Short Equity and Index Quote       | space, A B C F I O R T X Y| 29 + BBO appendage (0/10/20) |
| C        | Administrative (free text / FLEX)  | space                     | 14 + Message Data Length (max data 200) |

| R        | Series Mapping Message             | A                         | 155 |
| Y        | Underlying Value                   | space, I                  | 27 |

The appendage length for k/q is determined from the BBO Indicator in the Message
Indicator field: single appendage (+10) for indicators C, G, K (Best Offer) and
M, N, P (Best Bid); double appendage (+20) for indicator O; otherwise +0. See 5.3.

New categories/types may be added; a decoder hitting an unknown category cannot
determine the message length and must abandon the remainder of the block (validate
against Block Size / Messages In Block).

### 2.4 Denominator codes (price scaling)

All prices and index values are transmitted as integers; a 1 byte alphabetic
Denominator Code gives the number of implied decimal places. Real value =
raw / denominator. Prices are restricted to 8 significant digits, non-negative.

| Code | Denominator | Decimal places | Allowed for                              |
|------|-------------|----------------|------------------------------------------|
| A    | 10          | 1              | Index, Premium, Strike, Underlying       |
| B    | 100         | 2              | Index, Premium, Strike, Underlying       |
| C    | 1,000       | 3              | Index, Premium, Strike, Underlying       |
| D    | 10,000      | 4              | Index, Premium, Strike, Underlying       |
| E    | 100,000     | 5              | Index, Premium, Strike, Underlying       |
| F    | 1,000,000   | 6              | Index, Premium, Underlying (not Strike)  |
| G    | 10,000,000  | 7              | Index, Premium, Underlying (not Strike)  |
| H    | 100,000,000 | 8              | Underlying only                          |
| I    | 1           | 0 (no fraction)| Index, Premium, Strike, Underlying       |

The Premium Price Denominator Code scales Premium, Bid, Offer, Open, High, Low,
Last and Net Change. The Strike Price Denominator Code scales Strike. The Index
Value Denominator Code scales Index Value / Bid Index Value / Offer Index Value.
The Underlying Price Denominator Code scales Underlying Price.

Short quotes (category q) carry no denominator codes: Strike Price Denominator is
implied 'A' (divide by 10) and Premium Price Denominator is implied 'B' (divide
by 100).

### 2.5 Expiration Block (3 bytes; categories a, d, f, k, q and R)

| Field            | Rel. Offset | Length | Type  | Notes                              |
|------------------|-------------|--------|-------|------------------------------------|
| Expiration Month | 0           | 1      | ASCII | A-L = Jan-Dec CALL, M-X = Jan-Dec PUT |
| Expiration Day   | 1           | 1      | NUM   | 1 - 31                             |
| Expiration Year  | 2           | 1      | NUM   | 0 - 99, year = 2000 + value        |

Month code table: Call `A`=Jan `B`=Feb `C`=Mar `D`=Apr `E`=May `F`=Jun `G`=Jul
`H`=Aug `I`=Sep `J`=Oct `K`=Nov `L`=Dec; Put `M`=Jan `N`=Feb `O`=Mar `P`=Apr
`Q`=May `R`=Jun `S`=Jul `T`=Aug `U`=Sep `V`=Oct `W`=Nov `X`=Dec.
Decode: call if code <= 'L' (month = code - 'A' + 1), put otherwise
(month = code - 'M' + 1). The expiration block plus Security Symbol plus Strike
Price uniquely identifies an option series.

### 2.6 Security Symbol

5 bytes (4 bytes in category q short quotes). Alphanumeric, left justified, space
filled; symbol of the UNDERLYING security. Symbols longer than 4 characters must
use the long quote format. FLEX series have a numeric in the first character of
the symbol and are reported via Admin messages on line 4 only.

Test symbols (ignore for production analytics): ATEST, CBO, CBX, CTEST, IGZ,
MTEST, NTEST, PTEST, ZBZX, ZEXIT, ZIEXT, ZTEST, ZTST, ZVV, ZXIET, ZZK,
01A-12A, 01N-12N, 01P-12P, 01V-12V, 01Z-12Z (CTA) and ZAZZT, ZBZZT, ZCZZT,
ZJZZT, ZVZZC, ZVZZT, ZWZZT, ZXZZT (Nasdaq).

## 5. Categories "k" / "q" - Equity and Index Quote

Two formats for bandwidth: Long (k, 4 byte prices/sizes, 5 char symbol) and Short
(q, 2 byte unsigned prices/sizes, max 4 char symbol, implied denominators). Any
quote that does not fit the short constraints uses the long format.

Message Types for both: space = Regular Trading, `F` Non-Firm, `I` Indicative
Value (allowed after 4:15 pm), `R` Rotation, `T` Trading Halted, `A` Eligible for
Automatic Execution, `B` Bid contains Customer Trading Interest, `O` Offer contains
Customer Trading Interest, `C` Both contain Customer Trading Interest, `X` Offer
side Not Firm, `Y` Bid side Not Firm.
BBO-eligible types: space, A, B, O, C. BBO-ineligible: F, I, R, T (X offer side
only, Y bid side only).

Bid Price 0 + Bid Size 0 = cancel of the previous quote (Zero Quote; also published
by OPRA on behalf of a Participant on a "kill").

| Field                        | Rel. Offset | Length | Type   |
|------------------------------|-------------|--------|--------|
| Best Bid Participant ID      | 0           | 1      | Alpha  |

## Decoder Implementation Notes

1. **Per UDP packet**: parse the 21 byte block header; verify Version == 6 and
   Data Feed Indicator == 'O'. Optionally verify Block Size against the UDP payload
   length and the Block Checksum (lower 16 bits of 32-bit byte sum excluding the
   checksum field). Then iterate Messages In Block messages starting at offset 21.
2. **Per message**: read the 12 byte header, compute the message length from
   Category (2.3) plus, for k/q, the BBO Indicator appendage (5.3), decode, advance.
   After the last message at most 1 pad byte (0x00) remains before Block Size.
   If an unknown Message Category is encountered, the remainder of the block cannot
   be walked - count it and resynchronize at the next packet.
3. **Message sequence numbers**: each message gets `blockSeqNo + indexInBlock`.
   Track per line; apply the H/C, H/K, H/N and retransmission exceptions (1.3).
   Rollover at 4,294,967,295 -> 1; sequence resets to 0 at start of each day.
4. **Timestamps**: only the block timestamp exists (epoch seconds + nanoseconds);
   all messages in a block share it. pcapTS gives the capture time.
5. **Prices**: convert integer price fields to real values with the applicable
   denominator code at decode time (2.4); short quotes use implied denominators
   'A' (strike) and 'B' (premium).
6. **Series identity**: (Security Symbol, Expiration Block, Strike Price) is the
   series key; the Expiration Month code also encodes call/put (2.5).
7. **A/B arbitration**: both streams carry identical blocks; dedupe on
   (line, sequence number) if capturing both.
8. **Consolidated book / NBBO**: OPRA disseminates per-Participant top of book
   quotes plus the OPRA-computed BBO via quote messages and their appendages.
   There are no order-level messages. Time-and-sales requires category a
   (apply cancel types A/C/E/G; types u/v and Trading Session Identifier 1 do not
   update OHLC).
9. **Test data**: production multicast can carry test data 6:15 - 11:00 pm ET
   (regular lines) and 4:30 - 6:30 pm ET (GTH lines); filter by trading day /
   session, and ignore test symbols (2.6).

## 7. Flat Parquet Schema (DuckDB / libduckdb)

One row per decoded OPRA message (all categories, including Control). The schema is
flat: the union of every column in the protocol, with fields that have identical
meaning across message types sharing a single column (symbol, strikePrice,
bidPrice/offerPrice shared by k/q/f, volume shared by a/f, openInterestVolume
shared by d/f). Columns not present in a given message type are NULL, which
Parquet stores at negligible cost.

Type mapping rules:

- OPRA 1 byte unsigned   -> UTINYINT   (Parquet INT32 / UINT_8)
- OPRA 2 byte unsigned   -> USMALLINT  (Parquet INT32 / UINT_16)
- OPRA 4 byte unsigned   -> UINTEGER   (Parquet INT32 / UINT_32)
- OPRA ASCII char/string -> VARCHAR, space padding stripped, single spaces kept
                            (e.g. msgType space = VARCHAR ' '), empty -> NULL
- Prices / index values  -> DECIMAL(20,8), raw integer divided by the applicable
                            denominator (2.4) via duckdb_append_double; covers all
                            denominator codes A-I including the 8 byte Underlying
                            Price (8 significant digits max per spec)
- Timestamps             -> UBIGINT raw nanoseconds since epoch (pcapTS and
                            blockTimestampNS)

Denominator codes are consumed by the conversion and not stored as columns. The
raw Expiration Month code is stored plus derived putCall / numeric month / full
year columns for direct querying.

```sql
CREATE TABLE opra (
    -- capture / transport layer (every row)
    pcapTS                 UBIGINT,        -- pcap timestamp, ns since epoch
    lineNumber             USMALLINT,      -- OPRA line from classifier (1-96, 220, 201-204)
    feedStream             VARCHAR,        -- 'A' or 'B' multicast stream
    retransmission         VARCHAR,        -- 'V' if retransmitted block, else NULL
    sessionIndicator       UTINYINT,       -- raw byte: 0 RTH, 1-5 GTH day, 0x58 ('X') OPRA generated GTH
    blockTimestampNS       UBIGINT,        -- block timestamp, ns since epoch
    blockSeqNo             UINTEGER,       -- block sequence number as transmitted
    msgSeqNo               UINTEGER,       -- blockSeqNo + index of message within block

    -- message header (every row)
    participantId          VARCHAR,        -- exchange code (2.2)
    msgCategory            VARCHAR,        -- a d f k q C H R Y
    msgType                VARCHAR,        -- type within category (space kept as ' ')
    msgIndicator           VARCHAR,        -- BBO indicator for k/q, else NULL
    transactionId          UINTEGER,
    participantRefNo       UINTEGER,

    -- option series identity (a d f k q R)
    symbol                 VARCHAR,        -- underlying symbol, space padding stripped
    expirationMonthCode    VARCHAR,        -- raw A-X code
    putCall                VARCHAR,        -- derived: 'C' or 'P'
    expirationMonth        UTINYINT,       -- derived: 1-12
    expirationDay          UTINYINT,       -- 1-31
    expirationYear         USMALLINT,      -- derived: 2000 + raw
    strikePrice            DECIMAL(20,8),

    -- a: Equity and Index Last Sale
    volume                 UINTEGER,       -- a (trade size), f (daily volume)
    premiumPrice           DECIMAL(20,8),  -- trade price
    tradeIdentifier        UINTEGER,       -- future use, currently 0
    tradingSessionId       UTINYINT,       -- 0 regular, 1 extended

    -- d: Open Interest (also f)
    openInterestVolume     UINTEGER,

    -- f: Equity and Index End of Day Summary
    openPrice              DECIMAL(20,8),
    highPrice              DECIMAL(20,8),
    lowPrice               DECIMAL(20,8),
    lastPrice              DECIMAL(20,8),
    netChange              DECIMAL(20,8),  -- signed
    underlyingPrice        DECIMAL(20,8),

    -- k/q: Equity and Index Quote (bidPrice/offerPrice also f)
    bidPrice               DECIMAL(20,8),
    bidSize                UINTEGER,
    offerPrice             DECIMAL(20,8),
    offerSize              UINTEGER,

    -- k/q BBO appendages (NULL when no appendage)
    bestBidParticipantId   VARCHAR,
    bestBidPrice           DECIMAL(20,8),
    bestBidSize            UINTEGER,
    bestOfferParticipantId VARCHAR,
    bestOfferPrice         DECIMAL(20,8),
    bestOfferSize          UINTEGER,

    -- C: Administrative
    adminText              VARCHAR,        -- raw message data, printable ASCII

    -- R: Series Mapping
    multicastLineNumber    USMALLINT,      -- assigned output line 1-96

    -- Y: Underlying Value
    indexValue             DECIMAL(20,8),  -- type ' '
    bidIndexValue          DECIMAL(20,8),  -- type 'I'
    offerIndexValue        DECIMAL(20,8)   -- type 'I'
);
```

## 8. UDP Multicast Addressing (Lines / Groups / Ports)

Source: OPRA_Common_IP_Multicast_Distribution_Network.pdf (NMS network spec v1.59).
SIAC allocates 224.0.200.0 - 224.0.207.255. Every OPRA line is delivered as two
redundant streams with identical payload and sequence numbers: Data Stream A and
Data Stream B (different multicast group, SAME UDP port). Line = (multicast group,
UDP destination port) pair.

### 8.1 OPRA Regular Session, lines 1 - 96

Fully patterned; for line N in 1..96:

| Feed                 | Stream | Multicast Group     | UDP Port    |
|----------------------|--------|---------------------|-------------|
| Production           | A      | 224.0.204.N         | 45000 + N   |
| Production           | B      | 224.0.206.N         | 45000 + N   |
| Retransmission       | A      | 224.0.204.(127 + N) | 46000 + N   |
| Retransmission       | B      | 224.0.206.(127 + N) | 46000 + N   |
| Playback Test        | A      | 224.0.205.N         | 47000 + N   |
| Playback Test        | B      | 224.0.207.N         | 47000 + N   |

(e.g. line 1 production A = 224.0.204.1:45001, line 96 production B =
224.0.206.96:45096, line 40 retransmission A = 224.0.204.167:46040.)

### 8.5 Traffic distribution over lines (what to expect per line)

- With dynamic symbol rebalancing (v6.3+, current): each root symbol maps to
  1 - 16 (possibly non-consecutive) lines of 1 - 96, reassigned nightly; all
  messages for a given series stay on one line for the day. The mapping arrives
  via Series Mapping Messages (line 220 carries ALL of them) and the nightly CSV.
- Line 4 only: Administrative messages (category C, incl. FLEX), any symbol with
  a numeric first character, Underlying Value (Y) messages.
- All lines 1 - 96: Control messages; H/K Reset selectively on the affected line.
- GTH session uses lines 201 - 204 (204 = admin/numeric-first line) with a static
  symbol split (A-, S-, U-, V- alphabetical ranges by put/call and odd/even
  expiration day; spec Appendix B).
- Recipients must handle any symbol on any line.

### 8.6 Decoder filtering notes

- To identify OPRA traffic in a mixed capture, match UDP destination (group, port)
  pairs from 8.1 - 8.3. Quick prefix filters: 224.0.204.0/25 and 224.0.206.0/25
  (production incl. line 220), 224.0.204.128/25 and 224.0.206.128/25
  (retransmission), 224.0.205.0/25 and 224.0.207.0/25 (playback),
  224.0.200.0/28 and 224.0.200.128/28 (GTH production).
- The classifier can compute line number, stream (A/B) and feed type directly from
  the group/port arithmetic above; cross-check group vs port for consistency.
- A and B streams are identical: arbitrate/dedupe by (line, message sequence
  number).
- Daily schedule (ET, approximate): Start of Day 1:30 am, Open Interest 6:30 am,
  trading 9:30 am - 4:00 pm (equity) / 4:15 pm (index), EOD summaries
  4:25 - 6:05 pm, End of Day 6:05 pm. GTH: Start of Day 7:45 pm, session
  8:15 pm - 9:25 am. Test data possible outside these windows (see Decoder
  Implementation Notes, item 9).
